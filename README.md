# Карта сети — v2 (React + Tailwind)

Новый интерфейс редактора сети поверх **проверенного плана здания** (Козина 7, пом. 1080 + 1079).
Оформление — в стиле визитки [karpovai9696-spec.github.io/portfolio-website](https://karpovai9696-spec.github.io/portfolio-website/):
тёмная cyber-тема, фирменный жёлтый `#FCD116`, Montserrat / Inter / JetBrains Mono, точечная сетка.

**Онлайн-демо (без синхронизации):** https://karpovai9696-spec.github.io/netmap-v2/
**Рабочая версия с входом и realtime:** http://192.168.1.227:8092/ (внутренняя сеть)

## Вход и роли

| Логин | Кто | Роль | Права |
|---|---|---|---|
| `mikhail` | Михаил | администратор | вся схема: оборудование, кабели, слои, стены, пометки |
| `eduard` | Эдуард | инженер по строительным сооружениям | стены, двери, окна, проёмы и пометки; сетевые блоки (оборудование, кабели, слои сети, журнал, документация) скрыты |

- Администратор может **включить режим инженера без пароля Эдуарда**: кнопка «Режим инженера» в шапке
  (или пункт в меню пользователя). Включаются те же ограничения и скрытые сетевые блоки, что у роли
  `engineer`, но учётная запись остаётся администраторской; выключение — той же кнопкой.
- Пароли выдаются при первом развёртывании (см. `deploy-227.ps1`), меняются после входа: клик по своему имени в шапке → «Сменить пароль».
- Сессия хранится **72 часа**, токен — в localStorage браузера.
- Страница на GitHub Pages работает в **демо-режиме** (без сервера): вход и синхронизация доступны только на `.227`.

## Совместная работа в реальном времени

- Общий проект на сервере (`server/server.mjs`): WebSocket, операции по объектам, файл `project.json`.
- Видно, **кто онлайн** (аватары в шапке), **курсоры коллег** на чертеже и **ленту действий** («Эдуард изменил стену»).
- Изменения прилетают за доли секунды; всё сохраняется на сервере и переживает перезагрузку/перезапуск.
- Права проверяются **и на клиенте, и на сервере**: инженер не может изменить сеть даже в обход интерфейса.

## Что внутри

- **План — проверенная модель** из `out/*.csv`: левое крыло (пом. 1080) перестроено по
  актуальному плану БТИ — **13 помещений** (1–13) общей заявленной площадью 176.6 м²,
  с коридором 12, санузлами 10/11 и крыльцом; правое крыло (пом. 1079) — 18 помещений.
  Метры, единая система координат; блок 1080 слева, блок 1079 справа.
  Файл `src/correctPlan.ts` генерируется скриптом `tools/gen_plan.py`;
  левое крыло пересобирается `tools/rebuild_left_wing.py`.
- **Сеть офиса (документация)**: вкладка с выжимкой из `OFFICE-GATEWAY.md` v2.0 — архитектура
  VPN-шлюза (офис → Keenetic → srv-diamedika → VPS → интернет), адресация, сервисы/порты, DNS-схема,
  список сервисов в туннеле и команды диагностики. Кнопка **«Разместить на плане»** добавляет на чертёж
  Keenetic Viva, srv-diamedika (VPN-шлюз) и VPS (внешний узел) в новый слой **«VPN / шлюз»** со связями LAN
  и VPN-туннелем (UDP 8443). Доступно администратору; инженер видит документацию в режиме чтения. Данные документации хранятся только на сервере
  (`server/docs.json`, не в Git) и отдаются по API после входа — в публичной демо-сборке GitHub Pages их нет.
- **Слои**: интернет/СКС, телефония, ПК, серверы, видеонаблюдение, питание, перегородки, пометки —
  видимость, счётчики, «только активный / все».
- **Оборудование**: каталог (роутеры, коммутаторы, Wi-Fi, серверы, стойки, ИБП, ПК, МФУ, телефоны,
  камеры, регистраторы, розетки), паспорт узла (IP, VLAN, модель, высота монтажа).
- **Кабели**: 6 типов (СКС, оптика, телефония, видеонаблюдение, питание, прочее), ортогональная
  автоматическая трассировка, метраж с учётом опусков, кабельный журнал (CSV).
- **Редактирование существующих стен**: стены модели сняты с актуального чертежа и совпадают с ним
  (включаются в «Редакторе стен» или переключателем «Стены модели»; «Чертёж» скрывает подложку); их можно выделять, двигать,
  тянуть за концы, менять толщину и удалять. Undo/Redo — `Ctrl+Z` / `Ctrl+Shift+Z`.
- **Стены и проёмы**: рисование перегородок (клик-клик), перетаскивание, удаление, толщина;
  двери, окна и технологические проёмы ставятся кликом по стене, редактируются и удаляются;
  всё синхронизируется между пользователями и сохраняется в проекте/JSON.
- **Инструменты**: выбор, панорама, узел, кабель, перегородка, линейка, текст; undo/redo.
- **Печать / PDF**: отдельный печатный лист A4 landscape — только чертёж (светлая схема под печать),
  штамп с объектом/масштабом/площадью/датой и автором, легенда слоёв и сводка метража кабеля.
  Интерфейс, панели и фон на печать не попадают; лист всегда вписан в одну страницу.
- **Переворот плана на 180°**: кнопка ⟲ в нижней панели (рядом с сеткой/зумом) или клавиша **R**;
  ориентация сохраняется в проекте (localStorage / JSON). Подписи переворачиваются вместе с чертежом;
  для чёткости текст рендерится с `text-rendering=geometricPrecision`, центр поворота — целые пиксели,
  шрифты подписей увеличены.
- **Wi-Fi**: радиусы покрытия точек доступа.
- **Темы**: тёмная (визитка) и светлая инженерная.
- **Сохранение**: общий проект на сервере + автосохранение, экспорт/импорт JSON.

Пересобрать после обновления CSV:


## Сервер (вход + realtime)

Каталог `server/`:

- `server.mjs` — статика `dist` + REST (`/api/login`, `/api/me`, `/api/password`) + WebSocket `/ws`,
  роли, presence, сохранение проекта в `project.json`. Зависимостей нет (Node.js >= 18).
- `init-users.mjs` — создание `users.json` (scrypt-хэши); пароли генерируются и печатаются один раз.

Запуск локально:

```bash
node server/server.mjs        # PORT=8092 DIST=./dist DATA_DIR=./server
```

## Надёжность соединения

- Сессии хранятся в `sessions.json` (права 0600) и **переживают перезапуск сервера**;
  после рестарта/деплоя пользователи не разлогиниваются.
- Heartbeat каждые 8 секунд (порог 20 с) и события `online/offline/visibilitychange`: разрыв Wi-Fi/сон ноутбука определяется сразу, приложение переподключается без перезагрузки.
- При обрыве связи интерфейс не уходит на полноэкранную загрузку: остаётся открытым
  с баннером «Нет связи с сервером… идёт переподключение», затем автоматически
  синхронизируется.
- Если токен действительно истёк/недействителен (401), показывается экран входа,
  а не бесконечный цикл реконнекта.
- Сервер под cron-watchdog: при падении поднимается в течение ~2 минут.

## Производительность

- Шрифты (Montserrat / Inter / JetBrains Mono) **self-hosted**: 9 вариативных WOFF2 (~230 KB в сборке,
  браузер грузит только нужные подмножества ~177 KB), `font-display: swap`; Google Fonts CDN убран.
- JS разбит на `vendor` (React) и `app` — vendor кэшируется отдельно; итоговый gzip ~88 KB.
- CI: workflow **Site performance** (сборка + `site_perf.py check dist` + `find_broken_links.py --strict dist`), инструменты вендорены в `.github/rules/` с sha256.
- Изображений-фотографий нет (план — SVG-вектор), поэтому WebP/lazy-loading не применимы;
  `tools/site_perf.py check` проходит (PASS).
